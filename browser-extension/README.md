# 显式浏览器会话交接

这是本项目的社区授权交接扩展，不是 Meta OAuth，也不会使受限、未激活或已过期的账号获得额外权限。先在 Muse 官网正常登录并完成账号验证。

1. 构建并启动 Muse2API，打开本机管理页 `http://127.0.0.1:18689/`，生成一次性码。
2. Chrome 或 Edge 的扩展管理页开启开发者模式，选择“加载已解压的扩展程序”，仅选择本目录。开发者模式和加载扩展由使用者自己完成。
3. 切换到普通窗口中已登录的 `https://muse.ai/` 标签页，打开扩展，填本机管理端口和本次一次性码，点击明确授权按钮。当前版本拒绝隐私窗口，避免取到不同 Cookie store 的账号。
4. 返回本机管理页检查 `ready` 和加密保存状态。授权码短期有效且只能使用一次，失败后重新获取。

权限范围为 Muse 域名的 cookies、用户当前标签页，以及 `127.0.0.1` 网络请求。扩展只调用 `cookies.get` 读取 `hatch_sess`、`hatch_native_auth_device`、`hatch_vml`，不遍历其他网站 Cookie，不读取密码、Profile 或 storage，不使用扩展持久存储。会话仅在点击后的内存和本机交接请求中存在；扩展不打印请求内容，拒绝重定向和任意外部接收地址。

管理端口与业务 API 端口不同。服务器登录通过使用者自己的 SSH 本地转发接到服务器 loopback 管理端口，扩展仍只向 `127.0.0.1` 发送。不要把管理端口或 Cookie 导入入口直接放到公网；域名只反代业务 API。

服务器使用自己的 AES-GCM 密钥加密会话。密钥和密文都属于私密运行状态，不能提交 GitHub。会话过期、撤销或官网要求验证时，重新在官网完成登录并明确授权交接；不能承诺永久在线。

本目录的 Node 离线测试验证交接目标、域名、字段过滤与输入边界，不等于已在真实浏览器安装并登录验收：

```sh
node --test browser-extension/auth.test.mjs
```
