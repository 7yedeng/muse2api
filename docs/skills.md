# 配套 Skill 安装与使用

安装 Skill 只让代理获得操作方法，不会赋予 Muse 账号、浏览器或服务器权限。调用者仍使用自己的配置和显式授权。

## 选择 Skill

| Skill | 适用任务 | 不负责 |
| --- | --- | --- |
| `muse2api-local` | 本机安装、启动、管理端口、显式浏览器授权、持久化和重登录恢复 | 自动抓取浏览器会话、代理他人账号、修改既有中转站生产配置 |
| `muse2api-client` | 使用已授权 Base URL＋Key 调用文字、图片和视频，按原资源恢复查询与下载 | 网站后台管理、服务器登录、读取上游会话或浏览器资料 |

复制完整文件夹，而不只复制 `SKILL.md`。例如 Codex 用户可以复制到自己的 `~/.codex/skills/`，再刷新技能列表或重启当前代理环境。其他支持 Agent Skills 的工具按各自技能目录安装。不要同时覆盖已有的同名个人 Skill；先查看差异，再按自己的选择更新。

## 本机路线

```text
使用 $muse2api-local，在我指定的仓库目录配置并启动本机 Muse2API。
我会自己在 Muse 网页登录并点击扩展授权；不要读取浏览器 Cookie 或 Profile。
```

代理可以检查仓库、创建全新私密配置、构建和启动本实例，使用管理脚本检查状态。正常授权动作由用户在自己的浏览器扩展完成；一次性码不作为长期 API Key 使用。

## 调用路线

先按 [API 文档](api.md) 在使用者自己的终端设置 `MUSE2API_BASE_URL` 与 `MUSE2API_API_KEY`。远程站点应为 HTTPS。

```text
使用 $muse2api-client，通过我已配置的端点生成一段纸船漂浮的视频。
本作品 request-id 为 paper-boat-001。创建一次，随后只查原任务，下载到我指定的目录。
```

Skill 自带标准库 Python 客户端，安装后应按 Skill 相对路径找到 `scripts/muse_client.py`，不依赖原仓库的绝对路径。可调用 `models`、`chat`、`image`、`edit`、`video`、`status`、`wait`、`download`、`receipt`。

创建失败或等待中断时，代理应保留本地回执和原资源 ID。即使用户轮换了 Key，也不应该通过清空目录或换 request-id 来绕过未知状态。下载失败只恢复 GET，不重新制作作品。

## 凭据与文件范围

本机维护 Skill 使用明确指定的仓库及管理入口；调用 Skill 只使用调用者已配置的业务端点和 Key。两者都不搜索整个用户目录、浏览器 Profile、私人 SSH 文件或原维护者配置。

私密配置、会话密文、运行媒体和客户端回执都不是 Skill 安装内容，不进入 Git 或公开 ZIP。引用图片时仅使用用户明确提供的文件；不要自动遍历和上传整个文件夹。
