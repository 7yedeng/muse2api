# 交给 AI 的完整 SOP 提示词

复制下面整个文本块，填写方括号中的信息，再交给自己的 AI 助手。密钥、Cookie、邮箱验证码和会话文件不需要填写，也不要粘贴到聊天。

有仓库访问能力的 AI 可以读取公开仓库；没有访问能力时，下载仓库源码 ZIP，解压后将源码目录提供给支持本地文件的 AI。单独复制这个提示词不会让 AI 自动获得仓库内容、账号或执行权限。

```text
请根据 Muse2API 当前仓库，为我的环境整理并在授权范围内执行完整 SOP。

仓库：https://github.com/7yedeng/muse2api

我的目标：[仅获取 SOP / 本机安装使用 / 部署到自己的服务器和域名 / 接入 Sub2API 或 New API / 调用已有 API，可多选]
系统与终端：[例如 Windows + PowerShell，或 Linux + bash]
源码位置或版本：[本地源码目录、commit/tag；没有则使用当前公开版本并记录 commit]
我允许操作的范围：[仅生成文档，或我指定的目录、服务器、新实例和端口]
现有 API Base URL：[没有则留空；只填写公开入口，不填写 Key]
中转站类型与版本：[没有则留空]
希望使用的 Skill：[muse2api-local / muse2api-client / 都需要 / 仅查看说明]
本次作品要求与我提供的参考文件：[没有则填“本次不创作”]
输出目录：[我指定的目录]

先获取依据，再操作：
1. 用当前环境允许的方式，实际读取仓库 README.md、NOTICE.md、go.mod、docs/responsible-use.md 和 docs/verification.md，记录版本与已读文件。按目标读取 docs/local-setup.md、docs/server-deployment.md、docs/api.md、docs/relay-integration.md、docs/recovery.md、docs/capabilities.md、docs/skills.md，以及所选 Skill 的 SKILL.md 和 references。需要浏览器授权时同时读取 browser-extension/README.md。
2. 文档与实现不一致时核对相关源码，指出差异，采用当前明确实现的合同；不能仅凭项目名称或“OpenAI 兼容”猜字段。无法读取某份文件时直接说明缺失，不假称已读，也不根据记忆编造完整步骤；可以让我提供源码 ZIP 或缺失文档。
3. 先给出与我的目标匹配的简短执行顺序和验收标准。仅获取 SOP 时不修改环境、不登录、不启动服务。其他模式在我已经授权的范围内自主完成常规、可逆步骤，不重复索要同一授权；遇到会明显改变结果的关键缺失信息再问。不要扩展到无关账号、网站或既有服务。

配置与授权：
- 尊重 Meta 的官方条款、账号权益、配额和安全限制。本项目的 MIT 代码许可、技术调用成功与上游服务授权分别处理；个人用途不自动豁免条款。不通过换号、账号池或无限重试规避限制，不将教程当作共享或转售权益的许可；不声称获得 Meta 官方认证或背书。
- 只使用我自己的账号、服务器和调用凭据。密钥在我的本机环境或密钥管理方式中配置；不要让我把 API Key、AES 密钥、Cookie、密码或验证码发到聊天，不将它们打印到命令参数、日志、报告、Skill 或 Git。
- 全新配置使用当前仓库脚本生成；不覆盖已有私密文件，不遍历用户目录寻找旧 Key，不擅自读取其他实例的环境、服务器旧配置或浏览器 Profile、Cookie、storage state、密码。
- 我本人在 Chrome/Edge 正常登录 Muse，再按项目扩展说明明确点击授权。AI 不导出浏览器会话。说明这是社区会话交接，不是官方 OAuth；官方 Gadget 配对是另一条尚未接入本 HTTP backend 的路线。
- 默认是一份 Muse 会话、一个服务 API Key 的单用户实例。业务 API 默认 127.0.0.1:18688/v1，管理默认 127.0.0.1:18689；以实际配置为准。管理入口始终只在 loopback，服务器管理用我已授权的 SSH 本地转发。自有域名只用 HTTPS 转发业务 API，不公开管理路由或把 Key 放在前端。
- 分别验证进程可访问、会话 ready、加密保存、重启恢复和真实推理。持久化不代表上游登录永不过期；保留自己的密钥和数据目录，按恢复文档重新授权。

调用与能力边界：
- 根据当前 API 文档列明支持的端点、鉴权、模型别名、字段、输入格式与大小限制、输出格式。当前主要是文字、图片理解、图片生成编辑和异步视频；不要把未开放的音频、PDF、已有视频、工具调用、独立 TTS 或 seconds/size/seed 硬控制写成已支持。文字历史不等于复用了原生 SID，也不保证声线一致。
- 安装与状态检查不授权顺便创作。只有我在“本次作品要求”中明确指定作品，才提交相应创建；仅使用我指定的参考文件。使用稳定 request-id，先保存回执，每件图片或视频只创建一次。超时、断线、5xx、unknown 或失败后，保留原回执和资源 ID，仅查询、等待、下载原资源，不换编号、清空状态或重新 POST。无资源 ID 时说明定位限制，不重制来冒充恢复。
- 下载后核对完整传输、文件长度、摘要，以及适合该媒体的格式、尺寸、时长和音轨检查；技术文件通过、人工效果审核、上游实际能力分别报告。
- 接入 Sub2API/New API 时记录真实版本，区分 Muse2API 上游 Key 与中转站用户 Key，先验文字，再验图片和视频。当前仓库没有已验证的通用 Muse 视频中转插件，不能只填 Base URL 或改模型名就宣称全端点接通。需要媒体时按文档采用直连或自己网站后端转接，并检查用户归属；共享上游 Key 不自动提供多租户隔离。
- 如果需要安装 Skill，复制整个对应文件夹到我的工具支持的技能目录，不覆盖未知同名 Skill；分别说明本机维护 Skill 和 API 调用 Skill 的职责。
- 如果任务涉及修改开源仓库，先阅读当前贡献规则与审核要求，使用分支和 PR；不要自行绕过审核、直接推主分支或自动合并。

最后交付一份适合我当前系统的完整 SOP：
按“前置条件 → 配置与启动 → 本人浏览器授权 → 本机或 HTTPS 端点 → Skill/客户端调用 → 验收 → 持久化与重新登录 → 故障恢复和回退”的顺序，给出可以复制的命令、必要的手动步骤、预期结果与停止条件。只使用占位符表示敏感值。补充当前端点和输入输出对照、所选中转站接入范围，以及其他路线的文档链接。
结尾列出已经实际执行并通过的项目、未执行或未验证的项目、仍需我完成的具体动作。不要把 models、health、ready、mock 或缓存构建写成真实视频生成、冷启动下载或生产链路已经通过。
```

已有可用端点、只需创作时，可直接安装 [API 调用 Skill](../skills/muse2api-client/SKILL.md)；首次本机部署使用 [本机维护 Skill](../skills/muse2api-local/SKILL.md)。完整手册索引见 [README](../README.md)。
